# H5 application

## Scope

The H5 application uses Vue 3, Vite, strict TypeScript, Vue Router, Axios, and Vant. Its intentionally narrow scope is:

- login;
- enabled category navigation;
- published content list by category;
- video, document, and text detail viewing.
- per-user video resume and a home-page continue-watching card.

Do not add unrelated learning progress, favorites, search, comments, or profile features without an explicit request.

## Authentication

The unified site can return a `token` URL parameter. H5 stores it in session storage, removes it from the URL, and sends it as a Bearer token. HTTP 401 clears it and returns to `/login`.

The dev-only form `user / User@123` stores `dev:t1:u1`. This is a frontend convenience, not a backend password account.

## Categories and content

`HomeView.vue` loads the enabled category tree and published content. Selecting a first-level category includes its visible children; selecting a child filters to that child. Vant List provides pagination and PullRefresh reloads from page 1.

Keep an independent `requesting` guard separate from Vant's `loading` model. Vant may set `loading=true` before emitting `load`; using `loading` as an early-return guard suppresses the request entirely. `immediate-check=false` prevents a duplicate initial load because `onMounted` explicitly loads page 1.

## Content rendering

- VIDEO: native mobile video player with `playsinline`.
- DOC: display metadata and open/download the backend URL.
- TEXT: render backend-sanitized HTML.

List cover priority:

1. Explicit `coverUrl` uploaded in admin.
2. For VIDEO with no cover, `videoUrl` in the list response is loaded in a muted, metadata-preloaded video element and seeks near time zero to show the first frame.
3. Type-specific fallback artwork.

Video detail uses the same priority: an explicit `coverUrl` is passed to the native player's `poster`; when it is absent, the player seeks near time zero after metadata loads so mobile browsers render the video's opening frame instead of an empty black poster.

## Watch progress

Video detail starts from backend `progressSeconds`. It must wait until video metadata has loaded, seek to the backend card point, and only then enable progress writes. During playback, H5 saves the integer playback second after approximately five seconds of movement, and also saves on pause and component exit. The `ended` event saves the video duration as completion. The backend is authoritative; do not store resume position only in local storage.

Never allow an initialization-time `currentTime=0` from pause, refresh, or component teardown to overwrite a positive saved card point. A positive unfinished card point survives every refresh and route visit. Only progress at the video duration hides it from continue watching.

The browser duration may differ from the integer duration uploaded by admin by a few seconds. Ordinary progress writes must cap at `duration - 1`; only the actual media `ended` event sends the full duration. This prevents premature completion near the end.

Development HMR, network recovery, or the browser's media pipeline may reload the `<video>` element without a route change. Keep a short-lived, timestamped in-session latest-positive-second cache, disable writes during `loadstart` / `emptied`, and re-seek after metadata loads. On `pagehide`, persist the last known second with a keepalive request so a refresh cannot lose progress before a normal Axios request finishes. The cache expires after five minutes; the backend remains authoritative and stale local values must never permanently override it.

The home page requests `/contents/continue-watching` independently of category filters and shows at most one latest unfinished video. Its explicit cover has priority over the first-frame fallback. Clicking the card opens the normal video detail route, which resumes from the returned user-specific card point.

The list cover must not set Vant Image's `lazy-load` prop unless the Vant Lazyload plugin is installed. Without that plugin, the rendered image can keep an empty `src` even though `coverUrl` is valid.

DOC items are separated into a `资料文库` section in the home list. Backend business type `DOC` covers several actual file formats, so `DocumentCard.vue` must derive PDF/DOC/PPT/XLS presentation from the final suffix of `fileName`; do not use the coarse business type or MIME for this UI classification. It renders a distinct SVG icon and color for each known family, uses a neutral FILE fallback for unknown suffixes, uses real `fileSize`, and shows the description when present. Do not invent page counts, read counts, or download counts because the backend does not store those values.

The backend must be restarted after introducing or changing response fields such as `videoUrl`; a running old Java process continues serving the old response shape.

All IDs are strings for the same snowflake precision reason as admin.

## Verification

Run from `h5/`:

```bash
npm run typecheck
npm run build
```

For data absence, inspect the live H5 API before changing UI code. Confirm backend port 8080, tenant, `PUBLISHED` state, and category visibility.
